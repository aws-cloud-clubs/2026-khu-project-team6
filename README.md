# 2026-khu-project-team6
# [Project] 맞춤형 대여 중개 및 AI 추천 플랫폼 요구사항 정의서

## 1. 프로젝트 개요 및 아키텍처 방향

- **서비스 형태**: 판매자(대여자)와 구매자(대여받는 자)를 연결하는 P2P/B2C 대여 중개 매칭 플랫폼
- **핵심 UI/UX**: 사용자가 필요한 물품 리스트를 체크하면 해당 카테고리 상품만 모아서 커스텀하게 보여주는 방식
- **개발 환경**: Windows OS 기반 로컬 개발 및 빌드 환경
- **클라우드 환경**: AWS (비용 제약을 극복하기 위해 Serverless 및 가성비 아키텍처 지향)

## 2. 핵심 기능 요구사항 (Domain & Features)

### A. 상품 및 카테고리 관리 (판매자)

- **카테고리 단일 등록**: 판매자는 무조건 '개별 카테고리'에만 상품을 등록할 수 있음 (끼워팔기 방지).
- **카테고리 분류**:
    - 🎤 콘서트: 울트라 핸드폰, 대포카메라, 응원봉, 손풍기, 보조배터리, 쌍안경, 돗자리, 기타
    - 🎓 졸업사진: 학사모, 졸업가운, 꽃다발, 정장, 구두, 기타
    - ✈️ 여행: 돼지코, 캐리어, 디카, 보조배터리, 고프로, 여행용 와이파이(에그), 기타
    - 🏕️ 캠핑: 텐트, 타프, 쉘터, 침구, 계절용품, 조리도구(화로, 코펠, 버너 등), 식기, 의자, 테이블, 가구, 타포(그늘막), 수레, 기타
    - 💍 결혼식: 하객룩, 구두, 넥타이, 기타
    - 💼 면접: 면접룩, 구두, 기타
    - 🏖️ 페스티벌: 의상, 방수팩, 선글라스, 기타
- **정교한 카테고리 메타데이터**: 판매자가 등록 시 카테고리를 정확히 지정하도록 유도하는 유효성 검증 로직 필수. (판매글 등록 시 무조건 카테고리/세부분류 정리)

### B. 하이브리드 개인화 필터링 및 대여 매칭 (AI 챗봇 + 체크박스 연동)

- **듀얼 컴포넌트 인터페이스**: 화면은 [AI 상담 챗봇]과 [카테고리별 세부 물품 체크박스 리스트]가 양옆으로 배치된 구조를 가집니다.
- **실시간 UI 동기화 (WebSocket / Server-Sent Events)**:
    - 사용자가 챗봇과 대화(예: "이번 주말에 처음으로 캠핑 가는데 뭐가 필요할까?")를 진행하면, AWS Bedrock이 필요한 물품 카테고리를 추론합니다.
    - AI의 추론 결과에 따라, 화면 우측의 세부 물품 체크박스(예: 텐트, 타프, 버너 등)가 **사용자가 직접 누르지 않아도 실시간으로 체크(True) 처리**됩니다.
    - 물론 사용자가 체크박스에서 수동으로 체크를 추가하거나 해제할 수도 있습니다.
- **조건 확정 및 전환**: 사용자가 최종적으로 체크박스 검토를 마치고 '이 조건으로 물품 찾기' 폼 제출(Submit) 버튼을 누르면 다음 페이지로 이동합니다.
- **개인화 피드 노출**: 다음 페이지에서는 사용자가 최종 제출한 체크박스 ID 배열(Array)을 기반으로, **해당 카테고리에 속한 판매자들의 실제 대여 상품들만 필터링(Filtering)되어 노출**됩니다.

### C. 실시간 알림 및 채팅 (WebSocket)

- 대여 예약 신청, 확정, 반납 알림 및 판매자-구매자 간 1:1 대여 상담 채팅 기능.
- 대규모 동시 연결을 안정적으로 유지하는 WebSocket 아키텍처 필수.

### D. AI 기반 기능 (AI Inference)

- ChatGPT 스타일의 AI 추론 기능 탑재 (예: 사용자의 일정/목적에 맞는 대여 물품 추천 및 상담).
- AWS Bedrock을 연동한 서버리스 AI 추론 파이프라인 구성.

### E. 에스크로 기반 보증금(Deposit) 정책

- **예치 구조**: 보증금은 제3자인 플랫폼이 수납하여 보관(Escrow)하며, 대여가 최종 정상 종료되면 구매자에게 환불됨.
- **연체 페널티**: 반납 예정 시간 초과 시, 일일 단위로 보증금 반환율이 자동 차감됨 (예: 1일당 20% 차감, 최대 5일 지연 시 보증금 전액 몰수 및 판매자 귀속).
- **파손 페널티**: 판매자가 반납 검수 시 파손 상태를 등록하면 보증금 반환이 '동결(Freeze)'되며, 플랫폼 중재 후 판매자에게 합의금으로 지급됨.

### F. 사기 방지 수령 인증 정책

- 구매자는 물품 배송 완료(또는 직거래 완료) 후 **3시간 이내에 구성품 전체 사진을 시스템에 업로드**해야 함.
- 기한 내 사진 미업로드 시, 초기 물품 하자나 구성품 누락에 대한 모든 책임(귀책사유)은 구매자 본인에게 전적으로 귀속됨을 시스템 문구 및 약관으로 강제함.

### G. 회원가입 및 사용자 인증 시스템

- **입력 필드**: 실명, 이메일, 전화번호, 닉네임, 비밀번호
- **필수 인증 프로세스**:
    - 사용자는 [이메일 인증]을 성공적으로 완료해야만 회원가입을 마칠 수 있음.
    - **이메일 인증 방식**: Supabase Auth의 기본 이메일 인증 기능을 활용. 회원가입 요청 시 Supabase가 자동으로 **가입 승인 링크(Confirmation Link)가 포함된 인증 메일**을 발송하며, 사용자가 해당 링크를 클릭하면 `is_verified` 상태가 `true`로 전환됨. 자체 인증번호(OTP) 생성·발송·검증 로직은 구현하지 않음.
    - 전화번호는 단순 텍스트 필드로 수집하되, 가입 시 별도의 SMS 발송 인증은 생략함 (추후 카드 등록 단계에서 보안을 보완).
    - DB 스키마에 인증 완료 여부 상태 플래그(`is_verified: boolean`) 및 인증 수단 데이터 기록.
- **Unique 제약 조건**: 시스템 내에서 '닉네임', '이메일', '전화번호'는 중복될 수 없으며, 가입 시 실시간 중복 체크 API 제공.

### H. 이메일 기반 로그인 시스템

- **인증 수단**: 가입 시 설정한 **[이메일]**과 **[비밀번호]** 조합으로 로그인을 수행.
- **세션/토큰 관리**: JWT(JSON Web Token)를 발급하여 사용자 인증을 유지하며, API Gateway 및 Lambda 핸들러에서 웹소켓(WebSocket) 연결 권한 검증 시 이 토큰을 활용함.

### I. 역할 기반 권한 제어 (RBAC - Role Based Access Control)

- **사용자 역할(Role) 분류**:
    - 비회원 (Guest): 상품 탐색만 가능.
    - 일반 회원 (User): 로그인 후 [체크리스트 맞춤 조회 폼 제출], [판매 글 등록], [1:1 채팅] 가용.
    - 관리자 (Admin): 시스템 전체 통제 및 일반 회원이 등록한 [부적절한 게시글 강제 삭제] 권한 보유.
- **접근 제어 정책 (인가 미들웨어)**:
    - **맞춤 체크리스트 및 폼 제출 기능**: 비로그인 유저가 접근 시 로그인 페이지로 리다이렉트하거나 JWT 토큰 인증 요구.
    - **판매자 상품 등록 기능**: 로그인 후 발급된 JWT 토큰 내 유저 권한이 `User` 이상일 때만 POST 요청 허용.
    - **게시글 강제 삭제 기능**: 관리자 전용 엔드포인트(예: `/api/admin/items/{item_id}`)를 개설하고, JWT 토큰 내 권한이 `Admin`인 경우에만 DELETE 요청을 승인하는 보안 로직 구현.

### J. 로그인 유저 전용 마이페이지 및 대여 관리

- **회원 정보 수정**:
    - 로그인한 유저는 자신의 비밀번호, 닉네임, 프로필 정보, 카드 정보를 수정할 수 있음 (실명, 이메일, 전화번호는 보안 및 사기 방지를 위해 변경 시 재인증 프로세스 도입 혹은 관리자 문의로 제한).
- **대여 내역 조회**:
    - 유저가 [내가 대여 중인 물품 리스트 / 과거 대여했던 내역 / 내가 빌려준(판매한) 물품 현황]을 상태별(예약 완료, 배송 중, 대여 중, 반납 대기, 종료)로 한눈에 볼 수 있는 조회 API 구현.
    - **직접 거래(DIRECT) 건의 경우**: 대여 내역 카드 내에 [대여자 1:1 채팅하기] 버튼 활성화 $\rightarrow$ 클릭 시 해당 거래의 기존 웹소켓 채팅방 채널로 즉시 리다이렉트.
    - **픽업존(PICKUP_ZONE) 이용 건의 경우**: 대여자와 컨택할 필요가 없으므로 [플랫폼에 문의하기] 버튼 활성화 $\rightarrow$ 클릭 시 플랫폼 관리자/고객센터와의 1:1 문의 채널로 즉시 이동.

### K. 반납 기한 임박 자동 알림 시스템 (Automated Notification)

- **백엔드 배치 스케줄러 (Cron Job)**:
    - 백엔드(Express) 내부에 매일 특정 시간(예: 매일 오전 9시)에 구동되는 배치 스케줄러 탑재.
    - 대여 데이터베이스를 탐색하여 **[반납 예정일이 24시간~48시간 이내인 대여 건]**을 자동으로 필터링.
- **다중 채널 알림 연동 (SES / SMS)**:
    - 환경 변수(`NODE_ENV=production`) 기준, 조건에 매칭된 유저의 이메일(AWS SES) 또는 전화번호(SMS API)로 "반납 기한이 X일 남았습니다. 수령 당시 사진을 참고하여 모든 구성품과 함께 반납해 주세요." 안내 메시지를 자동 발송.
    - 테스트 환경(`NODE_ENV=test`)에서는 실제 발송을 스킵하고 모니터링 로그(Console) 기록으로 대체하여 비용 방어.

### L. 거래 유형별 동적 비즈니스 로직 및 인터페이스 제어

대여 게시글 등록 시 판매자는 거래 방식을 선택할 수 있으며, 구매자가 상세 페이지에서 선택한 [거래 유형]에 따라 시스템 동작이 조건부로 제어됨.

1. **옵션 A: 픽업존 이용 (플랫폼 창고 거점 거래)**
    - **인터페이스 제어**: 구매자와 판매자가 상호 컨택할 필요가 없으므로, 해당 상품 상세 페이지 및 주문서에서 **[1:1 채팅방 개설] 버튼을 비활성화(Disable)** 처리함.
    - **자금 흐름 및 정산 (플랫폼 에스크로)**:
        - 구매자는 대여료와 보증금을 '플랫폼 계좌/PG'로 전액 입금함.
        - 물품 수령 및 반납이 플랫폼 픽업존 창고를 통해 안전하게 확인 완료되면, 플랫폼 시스템이 수수료를 제외한 대여 대금을 판매자에게 자동 송금/정산함.
    - **이용 규정 명시**: 픽업존 이용 시 물품의 검수 및 대금 정산의 안전성을 플랫폼이 전적으로 보증한다는 신뢰성 고지 문구를 결제 화면에 필수 노출.
2. **옵션 B: 직접 거래 (유저 간 자율 거래 - 직거래/반값택배 등)**
    - **인터페이스 제어**: 상세 페이지 내 **[대여 문의 채팅] 버튼이 활성화**되며, 이를 통해 1:1 웹소켓 채팅방이 개설됨.
    - **자율성 및 책임 제한**: 배송 방식, 시간, 장소는 양자 간 자율 협의(알아서 진행) 사항임을 주문서에 고지함.
    - **AI 모니터링 적용**: 자율 거래인 만큼 사기 위험성이 높으므로, 기존 **AWS Bedrock AI 클린봇 정책을 100% 적용**하여 장외거래(카카오톡, 개인 계좌 유도) 및 부적절한 언행을 실시간 탐지하고 경고 팝업을 띄움.

### M. 거래 안전성 확보를 위한 결제 카드 사전 등록제 (Anti-Fraud Policy)

사기 방지 및 추후 파손/연체 페널티 이행 보장을 위해, 판매자와 구매자 모두 핵심 거래 기능 진입 전 '신용/체크카드 등록'을 필수로 완료해야 함.

1. **판매자 제약 조항 (글 등록 시 요구)**
    - **동작 방식**: 판매자가 [대여 글 등록] 버튼을 누르는 순간, 시스템은 해당 계정의 카드 등록 여부(`is_card_registered`)를 조회함.
    - **예외 처리**: 카드가 등록되어 있지 않은 경우, 글 등록 폼 진입을 차단하고 "안전한 대여 환경을 위해 결제 카드 등록이 필요합니다" 안내 팝업과 함께 [카드 등록 페이지]로 강제 리다이렉트(이동)함.
2. **구매자 제약 조항 (주문/결제 진행 시 요구)**
    - **동작 방식**: 구매자가 상품 상세 페이지에서 [대여하기/구매 버튼]을 누르기 직전, 시스템이 카드 등록 여부를 즉각 검증함.
    - **예외 처리**: 미등록 상태일 경우 주문서 작성 및 대금 결제 창 진입을 차단하고, 카드 등록을 완료해야만 대여 프로세스를 밟을 수 있도록 UI 및 API 레이어에서 이중 차단함.
3. **마이페이지(회원정보수정) 연동**
    - **카드 관리 컴포넌트**: 유저는 마이페이지(회원정보수정) 메뉴에 언제든지 진입하여 등록된 카드를 [확인 / 변경 / 삭제]할 수 있음.
    - **삭제 제약 조건**: 단, 현재 '대여 중'이거나 '반납 검수 대기(보증금 에스크로 진행 중)' 상태인 활성화된 주문건이 존재할 경우, 분쟁 해결 전까지는 등록된 카드를 삭제할 수 없도록 안전 로직(Lock)을 구현해야 함.

## 3. 기술 스택 및 AWS 인프라 조건 (AWS Services 3개 이상 사용)

- **Front-end**: React (TypeScript) -> AWS S3 + CloudFront(CDN)를 통한 정적 호스팅 배포
    - Figma 디자인 컴포넌트 아키텍처를 기반으로 UI를 구현할 예정이므로, 컴포넌트 재사용성을 고려한 설계 요망.
    - 웹사이트 형식으로 제작.
- **Back-end**: Express (Node.js) -> AWS Lambda (Serverless) 환경에 배포
- **Orchestration & Network**: AWS API Gateway
    - REST API 및 WebSocket API 프로토콜을 통합 오케스트레이션하여 Lambda 핸들러와 라우팅 연동.
    - 실시간 1:1 채팅을 위한 500개 동시 연결(Persistent Connection) 유지를 API Gateway 레이어에서 전담 처리.
- **Database**: Supabase (Serverless PostgreSQL) 또는 AWS DynamoDB 중 비용 $0 Free Tier 가용 옵션 채택
- **AI Engine**: AWS Bedrock (Claude 또는 하위 경량 모델 연동을 통한 챗봇 및 클린봇 구현)
- **비용 한도**: 개발/테스트 전체 인프라 비용 $30 이하 엄격 준수 (모든 컴퓨팅 및 자원은 이벤트 기반 서버리스 아키텍처로 구성)
- **모니터링 & 옵저버빌리티**: Prometheus + Grafana 아키텍처 연동
    - 시스템 및 애플리케이션 메타데이터 수집
    - 메트릭 실시간 시각화 대시보드 인프라 설계
- **인증/보안 (Authentication)**:
    - **이메일 인증**: Supabase Auth의 기본 이메일 인증 기능을 사용. 회원가입 시 Supabase가 가입 승인 링크(Confirmation Link)가 포함된 인증 메일을 자동 발송하며, 링크 클릭 시 계정이 활성화됨. 별도의 AWS SES 연동이나 자체 인증번호(OTP) 파이프라인은 구현하지 않음.
    - **비밀번호 저장**: Supabase Auth가 내부적으로 bcrypt 기반 단방향 해시로 처리하므로 별도 해시 로직 불필요. 커스텀 `users` 테이블에는 Supabase Auth의 `auth.users.id`를 외래키로 참조하여 프로필 데이터만 저장.
    - **세션/토큰**: Supabase Auth가 발급하는 JWT를 그대로 활용하여 API Gateway 및 Lambda Authorizer에서 검증.

## 4. 비즈니스 로직 및 성능/부하 테스트 조건 (Performance Specs)

부하 테스트 도구(k6 또는 Apache JMeter)를 통한 시나리오 검증이 가능하도록 아키텍처 및 핸들러 가용성이 설계되어야 함.

### A. 기본 부하 테스트 (Load Test)

- **조건**: 동시 접속자 50명 / 5분간 지속 시뮬레이션
- **목표 지표**: 평균 응답 시간(Latency) 500ms 이하, 오류율(Error Rate) 1% 미만 유지

### B. 스파이크 테스트 (Spike Test)

- **조건**: 평상시 10명 $\rightarrow$ 순간 200명 급증 $\rightarrow$ 다시 10명으로 감소하는 가파른 트래픽 그래프
- **목표 지표**: 스파이크 발생 후 60초 이내에 정상 응답 상태로 복귀, 스파이크 도중 최고 오류율 5% 미만 유지
- **대응 전략**: AWS Lambda 동시성(Reserved/Provisioned Concurrency) 제어 또는 아키텍처 레벨의 Auto Scaling 설계 반영

### C. AI 추론 트래픽 테스트 (AI Inference Scenario)

- **조건**: 사용자가 급증하여 Lambda + AWS Bedrock AI 추론 호출이 몰리는 상황 시뮬레이션
- **목표**: Bedrock API 호출 지연에 따른 서버 병목 방지 및 타임아웃 예외 처리, 정확한 응답시간 측정 로직 반영

### D. 웹소켓 지속 연결 테스트 (WebSocket Persistent Test)

- **조건**: 실시간 채팅/알림 서비스를 위해 500개의 동시 커넥션(500 Connections)을 끊어지지 않고 안정적으로 유지하는 테스트 시나리오 대응

### E. 환경별(Production/Test) 가변 인증 파이프라인

- **인증 인프라**:
    - **이메일 인증**: Supabase Auth의 내장 이메일 인증 기능을 사용. Supabase 대시보드에서 SMTP 설정(또는 Supabase 기본 메일 서버)을 통해 가입 승인 링크 메일이 자동 발송됨. AWS SES 직접 연동 및 자체 인증번호 발송 로직은 제거.
    - **문자 인증**: 가입 단계에서는 SMS 인증을 생략하며, 추후 카드 등록 단계에서 보안을 보완하는 방식으로 대체.
- **환경 변수(.env) 제어**:
    - `NODE_ENV=production` 일 때는 Supabase Auth가 실제 인증 메일을 발송하여 실사용자 인증 처리.
    - `NODE_ENV=test` 일 때는 Supabase Auth의 **이메일 인증 확인(Confirm email) 옵션을 비활성화**하거나, Supabase 로컬 개발 환경(Supabase CLI)의 Inbucket 메일 캐처를 활용하여 실제 메일 발송 없이 인증 플로우를 테스트. 외부 메일 API 호출 비용 및 차단 없이 부하 테스트(k6/JMeter) 수행 가능.
- **Supabase Auth 관련 환경 변수**:
    - `SUPABASE_URL`: Supabase 프로젝트 URL
    - `SUPABASE_ANON_KEY`: 클라이언트(프론트엔드) 공개 키
    - `SUPABASE_SERVICE_ROLE_KEY`: 서버(Lambda) 전용 서비스 롤 키 (절대 클라이언트에 노출 금지)
